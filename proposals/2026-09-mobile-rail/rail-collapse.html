S3 Proposal · Mobile Activity Rail · 2026-09Rail-Kollaps für Mobile — drei Varianten, Tag & Nacht

Problem: Die linke Aktivitäten-Leiste (~12 Kreise à 64 px, volle Höhe, ~20 % der Breite) dominiert den mobilen Bildschirm. Die Karte ist das Primärinstrument und muss zurückgewinnen. Kollabiert: ~40 px. Verfügbarkeits-Farben (amber/u.a.) erscheinen nur als Daten am Pin, nie als Dekoration.

Layer & Filter

Pros / Cons
  • + Minimaler Ruhezustand: eine 40-px-Pill, Karte fast voll sichtbar.
  • + Der aktive Filter bleibt als Instrumentablesung (Icon + Label + Count) permanent sichtbar.
  • + Bottom-Sheet folgt dem etablierten Mobile-Muster; Platz für Verfügbarkeits-Filter.
  • − Zwei Taps für einen Filterwechsel (Chip → Sheet → Zelle).
  • − Sheet verdeckt bei offenem Zustand die untere Kartenhälfte.

Pros / Cons
  • + Footprint halbiert sich (~56 px inkl. Padding statt ~112 px); Karte bleibt dominant.
  • + Ein Tap pro Wechsel — schnellstes Filter-Handling der drei Varianten.
  • + Aktiver Zustand als Inset-Goldring (Beam, kein Wash) auf tonalem Chip — token-konform.
  • − Ohne Labels nur per Icon erkennbar; Count-Badge braucht 16-px-Minimum.
  • − Bei 12+ Kategorien wird die Säule wieder hoch; Scrollen in der Säule ist fummelig.

Pros / Cons
  • + Linke Kante komplett frei — Karte plus Pin-Labels bekommen die volle Breite.
  • + Beschriftete Kategorien (Label + Count), kein Icon-Rätselraten.
  • + Skaliert linear mit Kategoriezahl — horizontales Scrollen ist das native Muster.
  • − Höhe von ~90 px über die volle Breite; kollidiert mit dem eigentlichen Bottom-Sheet.
  • − Aktive Kategorie rollt aus dem sichtbaren Bereich; Goldring-Inset braucht diszipliniertes Auto-Scroll.
  • − Daumenzone: Buttons liegen im schwersten Erreichbarkeitsband.
